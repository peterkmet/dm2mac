# Movies: PRD

## Goal

The port plays the movies of the PC version as the DOS launcher does: the Interplay splash picture, the FTL logo, and the intro before the start menu; the end movie and the credits after the party completes the game. The port uses the SVGA movies (640 × 480), the best quality of the PC version.

## Reader

The developer and the agents that write the implementation plan and the code.

## Scope

In scope:

- The SVGA movies `game/FTL`, `game/INTRO`, `game/END`, and `game/CREDITS`. Each file is a DOS player program with the Interplay MVE data after it.
- The splash picture `game/INTRPLAY.PCX`. The launcher shows it with `SPLASH`.
- The order of the launcher script of `IBMIOP.EXE`, the skip rules, the sound of the movies, and the movie state in the control socket.

Out of scope:

- The VGA movies (`*.VGA`) and `CREDITS.PCX`, which the VGA script shows instead of the credits movie.
- An option that turns the movies off.
- The turn-based mode. A separate PRD covers it.
- A differential test of the movie decoder against the original player.

## Acceptance

```gherkin
Feature: Movies
  Scenario: start without a save
    Given the game files in game/
    When build/dm2 starts without --save
    Then the splash picture shows for 3 seconds
    And the FTL movie plays, then the intro movie
    And then the start menu shows

  Scenario: start with a save
    When build/dm2 starts with --save tests/saves/start.DAT
    Then no movie plays and the game starts at once

  Scenario: skip in the vanilla mode
    Given the vanilla mode
    When the player clicks during the splash or the FTL movie
    Then the picture or the movie goes on
    When the player clicks during the intro, end, or credits movie
    Then that movie stops and the next step of the script starts

  Scenario: skip in the advanced mode
    Given the advanced mode
    When the player clicks during the splash or any movie
    Then it stops and the next step of the script starts

  Scenario: end of the game
    When the party completes the game
    Then the end movie plays, then the credits movie
    And then the program ends

  Scenario: restart
    When the player chooses RESTART in the save menu
    Then no movie plays and the start menu shows

  Scenario: missing movie
    Given game/FTL is missing
    When build/dm2 starts without --save
    Then the splash shows, then the intro movie plays, then the start menu shows

  Scenario: control socket
    Given build/dm2 --control PATH without --save
    When a client sends state during a movie
    Then the reply has "mode": "movie"
    When the client sends click
    Then the movie stops by the skip rules of the mode
```

## Invariants

1. `data/mve.c` and `data/pcx.c` decode from memory only. They do not read files, use SDL, or keep global state. The tests call them through `build/libdm2.dylib`.
2. The decoder does not read or write outside its input data and its frame buffers, also for damaged data.
3. The game rules, the saves, and the game screen do not change. The scale filters do not apply to the movies.
4. Coding standard rule 8 holds: `ui/` does not include `platform/`.
5. `main` returns `session.exit_code` as before. A skipped, damaged, or missing movie does not change it.
6. `build/dm2 --save PATH` opens no movie file and no `INTRPLAY.PCX`.

## Current state

- `docs/skull-formats.md` section 3: the SVGA option changes only the movies. The movies set VESA mode `0x101` (640 × 480). The launcher script of `IBMIOP.EXE` is `splash intrplay.pcx 3`, `ftl noabort`, `intro 640x350 wide`, the game, `end 640x350 wide`, `credits 640x350 wide`. The script table is at the decompressed offset `0x3f62`.
- Each movie file is the same 16-bit DOS player (MZ) with the MVE data after it. The last `Interplay MVE File` signature in the file starts the data.
- The MVE data of the four SVGA movies (from a parse on 2026-10-10):

  | Movie | Frames (opcode `0x07`) | Video data frames (opcode `0x11`) | Timer (µs × subdivision) | Length |
  |---|---|---|---|---|
  | `FTL` | 66 | 36 | 10416 × 8 | about 5.5 s |
  | `INTRO` | 217 | 217 | 10416 × 8 | about 18 s |
  | `END` | 600 | 588 | 10416 × 8 | about 50 s |
  | `CREDITS` | 360 | 360 | 12500 × 8 | about 36 s |

- Opcodes in all four: `0x00` end of stream, `0x01` end of chunk, `0x02` create timer, `0x03` init audio, `0x04` start or stop audio, `0x05` init video buffers (version 2: 54 × 40 blocks of 8 × 8, that is 432 × 320, 8-bit), `0x07` show frame (version 1), `0x08` audio frame, `0x09` silent audio frame, `0x0a` set video mode (640, 480, `0x101`), `0x0c` palette, `0x0f` decoding map, `0x11` video data (version 3), `0x13` (meaning not known yet).
- Init audio (version 0) has the flags `0x0001` and the rate 22050 Hz. By the public MVE descriptions, flag bit 0 is stereo, bit 1 is 16-bit, and bit 2 is compressed: the audio is stereo, 8-bit, and not compressed. The plan verifies this in the player code.
- `INTRPLAY.PCX`: PCX version 5, RLE, 8 bits per pixel, 1 plane, 320 × 200, with a 256-color palette at the end of the file.
- `platform/main.c` runs the main loop and the modal loops. `ui/` cannot call `platform/`. The music reaches the sound output through a callback (`plat_audio_music(music_render)`). The mixer runs interleaved stereo at `SOUND_OUTPUT_RATE` (44100 Hz). `plat_present` (`platform/platform.c`) presents the 320 × 200 `fb` with an integer scale.
- `session_complete` sets `session.completed` and calls `session_quit`, which sets `main_loop.quit`. `main` then leaves the main loop and calls `control_close`, `music_quit`, and `plat_quit`. `EXIT_RESTART` makes `main` start the program again without `--save` (`execvp`). The comment there says that the DOS launcher starts the game again.
- `control.c` `send_state` takes `mode` from `input_get_mode()` through `mode_names[]`.

## Requirements

1. **Order.** Without `--save`, the program shows the splash picture for 3 seconds, plays `FTL`, then `INTRO`, then shows the start menu. With `--save`, it plays no movie at the start. After the game ends with `EXIT_COMPLETED`, it plays `END`, then `CREDITS`, then ends. After `EXIT_QUIT`, `EXIT_PARTY_DEAD`, and `EXIT_GAME_LOST` it plays no movie. A restart (`EXIT_RESTART`) starts the program again without movies. A missing movie file, a missing `INTRPLAY.PCX`, a damaged movie, or a movie whose video mode (opcode `0x0a`) is not 640 × 480 is a failed step: the port skips it, and the script goes on.
2. **Skip.** A mouse click skips. Vanilla mode: a click does not stop the splash or `FTL`. `FTL` has `noabort` in the script; for the splash this is the user's choice, because the script gives it a fixed 3 seconds. A click stops `INTRO`, `END`, and `CREDITS`. Advanced mode: a click stops the splash and each movie. A key does not skip. A quit event of the window during the splash or a movie stops the script and ends the program with the exit code of the session.
3. **Decoder.** `data/mve.c` parses the MVE stream (chunks and opcodes) and decodes the palette (`0x0c`), the decoding map (`0x0f`), the 8-bit Interplay video codec (`0x11`), and the audio frames (`0x08`, `0x09`). The decoder skips an unknown opcode by its length, also `0x13`, until the plan finds its meaning in the player code. If `0x13` changes the picture, the plan adds its decode as a task.
4. **Picture.** `data/pcx.c` decodes `INTRPLAY.PCX` (8-bit RLE with a 256-color palette).
5. **Display.** The movie screen is 640 × 480 with the 432 × 320 video in the center, as the VESA mode of the original. The window shows it with black borders, the 4:3 aspect, and the largest integer scale that fits, as the game screen. The splash picture shows on the 320 × 200 game screen, as the game. The game screen comes back after the movies.
6. **Sound.** The movie audio plays through the SDL sound output at full volume, as the separate DOS player. `ui/movie.c` converts the samples to 16-bit stereo at `SOUND_OUTPUT_RATE` and repeats each sample pair two times. The game music does not play during a movie. The frames follow the timer of the MVE data.
7. **Layers.** `ui/movie.c` holds the script order, the skip rules, and the frame and audio state. `platform/main.c` drives its frames and gives the audio callback, as for the music. `platform/platform.c` gets `plat_present_movie`: a 640 × 480 8-bit frame with its palette and its own texture; `platform/platform.h` declares it. `main` plays the start movies before the start menu, and `END` and `CREDITS` after the main loop ends with `EXIT_COMPLETED`, before `control_close`, `music_quit`, and `plat_quit`.
8. **Control socket.** The movie loop serves the control requests between frames. `send_state` gives `"mode": "movie"` while a flag of `ui/movie.c` says that a movie or the splash plays; else the mode of the input as before. `click` skips by requirement 2. `screenshot` saves the game screen as before (320 × 200).
9. **Docs.** `docs/skull-formats.md` gets the MVE and PCX formats as the port reads them, the launcher order, and the skip rules. In section 3 it replaces "Movies are out of scope" with a reference to the movie section. `docs/llm-control.md` gets the mode `movie`. `docs/manual-test-checklist.md` gets the checks of the movies.

## Decisions

| Topic | Decision | Reason |
|---|---|---|
| Movie version | SVGA (640 × 480). | User choice: the best quality of the PC version. |
| Test reference | No reference for the decoder. Tests check only the parser and the data formats: opcode counts, frame counts, timer, buffer sizes, palette, the PCX size and palette, and that the decode of all frames stays inside the data. The developer checks the picture and the sound manually. | User choice. The player is a 16-bit DOS program; the emulator harness runs 32-bit LE code only. |
| Skip | A mouse click. Vanilla: no skip of the splash and `FTL`. Advanced: a click stops everything. A key does not skip. | User choice: a skip is a click. |
| Start with `--save` | No movies at the start. | `--save` is a developer option of the port; the launcher of the original has no such option. |
| Restart | No movies. | The DOS launcher starts only the game again (comment in `main.c`). The plan verifies it in the script table. |
| End movies | Only after `EXIT_COMPLETED`. | The end movie shows the completed game. The plan verifies the exit codes in the script table. |
| Option to turn the movies off | None. | User choice. Tests and the control socket skip with a click. |
| Screen of a movie | 640 × 480 with black borders, the largest integer scale, no scale filter. | The original sets VESA mode `0x101`. The game screen also uses an integer scale. The filters of the port are made for 320 × 200. |
| Splash screen | The 320 × 200 game screen. | `INTRPLAY.PCX` is 320 × 200. |
| Movie mode in the state | A flag of `ui/movie.c`, not a new input mode. | No change of the input modes of the game (invariant 3). |
| Volume | Full volume, not the game sound setting. | The original player is a separate program that does not read the game settings. |
| Layer of the loop | Script and state in `ui/movie.c`; frames and audio in `platform/main.c`, present in `platform/platform.c`. | Rule 8: `ui/` does not include `platform/`. The music uses the same callback pattern. |
| Screenshot during a movie | The game screen (320 × 200), as before. | The control protocol has a fixed 320 × 200 screenshot; the tests do not need a movie screenshot. |
| Failed step | The port skips it, and the script goes on. | The game must start also with a bad, missing, or VGA movie file. |

## Known consequences

- A start without `--save` takes about 26.5 seconds longer (3 + 5.5 + 18 s). In the vanilla mode, 8.5 seconds of it cannot be skipped.
- Every control-socket run and every manual check without `--save` must send a click before the menu, and wait 8.5 seconds in the vanilla mode.
- The end of the game takes up to 86 seconds longer.
- The movies ignore the sound volume setting of the game.
- `docs/skull-formats.md` section 3 says that movies are out of scope. Requirement 9 changes this sentence.

## Risks

- The developer checks the synchronization of the picture and the sound manually only.
- The launcher conditions (exit codes, restart) come from the script table of `IBMIOP.EXE`. The documentation has only the strings now.
- The script passes `640x350 wide` to `INTRO`, `END`, and `CREDITS`. Its meaning is not known. The plan reads it in the player code. If the player stretches the video, the run stops and asks the user before it changes requirement 5.
